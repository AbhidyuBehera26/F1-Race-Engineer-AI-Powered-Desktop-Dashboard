# F1 Race Engineer Dashboard

A desktop application for Formula 1 telemetry visualization and race engineering debriefs. Built with Python, PyQt6, FastF1, Matplotlib, and an offline local LLM via Ollama (Llama 3.1 8B).

---

## Features

- **Telemetry Plotting:** Renders speed, throttle, and brake traces aligned by track distance for session fastest laps using FastF1 data.
- **Race Engineer Debrief:** Uses a local Llama 3.1 8B model via Ollama to query circuit setup notes, tyre compound allocations, aerodynamic guidelines, and braking zones.
- **Live Weather Integration:** Queries Open-Meteo for live track and ambient temperatures at 10 Grand Prix circuits.
- **Tyre Pressure Adjustments:** Automatically calculates cold-track pressure adjustments in Python based on live surface temperature before displaying recommendations.
- **Stint Strategy Analysis:** Includes a standalone analysis script (`stints.py`) that parses official race stint data from OpenF1.

## Architecture

The application has a split-pane interface:

```text

│          RACE ENGINEER CHAT           │          LAP TELEMETRY VIEWER          │
├───────────────────────────────────────┼────────────────────────────────────────┤
│ • Local Llama 3.1 8B (via Ollama)     │ • 2024 Belgian GP Lap 44 Telemetry     │
│ • Circuit setup and tyre notes lookup │ • Speed trace (74 to 319 km/h)         │
│ • Live Open-Meteo weather integration │ • Throttle trace (0 to 100%)           │
│ • Calculated tyre pressure offsets    │ • Stepped brake trace (0 / 100 on/off) │
│                                       │                                        │
│ [ Tyres for Spa? ] [ Brake zones ]    │ [ Refresh Telemetry ]                  │
└───────────────────────────────────────┴────────────────────────────────────────┘
```

- **Left Panel (`chat_panel.py`):** Chat interface with prompt suggestion buttons. Handles communication with the local LLM running in a background `QThread`.
- **Right Panel (`telemetry_panel.py`):** Displays the multi-tier telemetry plot generated by Matplotlib. Can be refreshed asynchronously without blocking the UI.

## Technical Details

### Telemetry & Brake Sensor Data
Public Formula 1 timing feeds (FastF1 and the FIA live timing stream) provide speed in km/h and throttle as a percentage (0–100%). However, hydraulic brake line pressure (bar/PSI) is kept private by teams. Public feeds only broadcast a binary brake signal: `0` (off) or `100` (on). 

The telemetry panel plots this as a stepped square trace (`matplotlib.pyplot.step(..., where='post')`) rather than an interpolated curve, accurately showing the 8 braking zones across Spa-Francorchamps.

### 2024 Belgian GP Stint Distribution
The included `stints.py` script queries the OpenF1 session API (`session_key=9574`) and computes stint lengths across all 58 driver stints from the 2024 Belgian Grand Prix:

```text
Compound   Stints   Min    Median   Mean     Max
------------------------------------------------
HARD       27       5      19       19.6     34
MEDIUM     27       1      11       11.3     24
SOFT       4        1      1        3.0      8
```

Hard tyre stints ranged from 5 to 34 laps with a median of 19 laps. Two-stop drivers ran aggressive 14–19 lap Hard stints, while one-stop strategies ran 27 to 34 laps.

### Setup Notes and Weather Calculations
Circuit engineering guidelines, baseline pressures, and camber limits are stored in `app/knowledge_base.txt`. 

When querying tyre information for Spa, `engineer.py` fetches the live track surface temperature via Open-Meteo. If the track surface is below 30°C, a cold-track adjustment of +1.5 to +2.0 PSI is computed in Python and added to the baseline minimums (Front 26.0 PSI, Rear 24.5 PSI) before answering. For circuits where tyre allocations are not documented (such as Monza), the search returns an explicit note that data is unlisted.

## Setup & Installation

### 1. Prerequisites
- Python 3.11 or later
- [Ollama](https://ollama.com) installed and running

### 2. Clone and Install Dependencies
```bash
git clone https://github.com/AbhidyuBehera26/F1-Race-Engineer-AI-Powered-Desktop-Dashboard.git
cd F1-Race-Engineer-AI-Powered-Desktop-Dashboard
pip install -r requirements.txt
```

### 3. Pull the Local Model
Download the Llama 3.1 8B model via Ollama:
```bash
ollama pull llama3.1:8b
```

### 4. Run the Dashboard
On Windows:
```bash
py run.py
```
On Linux / macOS:
```bash
python3 run.py
```

### 5. Run the Stint Analysis Script
To run the standalone stint distribution script:
```bash
python stints.py
```
This runs using standard library Python modules with zero external pip dependencies.

## Optional OpenAI Fallback

If you want to use OpenAI instead of running Ollama locally:
1. Create a file named `openAI_key.txt` in the root folder.
2. Paste your OpenAI API key inside.
3. Start the application without Ollama running. It will detect the key and switch to GPT-4o.

*(Note: `openAI_key.txt` is in `.gitignore` and is never committed to Git).*

## Example Queries

- **"Tyres for Spa today?"** — Fetches live Spa track weather and returns the 2024 Pirelli nomination (Hard C2, Medium C3, Soft C4), starting minimums, and temperature-adjusted pressures.
- **"Best aero for Monza?"** — Returns low-drag rear wing recommendations (2° to 4° angle).
- **"Analyse the brake zones"** — Explains the braking points on the telemetry plot, including the Bus Stop chicane and La Source.
- **"Tyres for Monza?"** — Indicates that tyre allocations for Monza are not documented in the local reference notes.
